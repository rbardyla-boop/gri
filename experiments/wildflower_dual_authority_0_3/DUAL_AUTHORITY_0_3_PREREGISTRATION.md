## Alternate-evidence Metric A

The 0.3 challenge guarantees `40` valid positive events per challenge episode
before any scientific result is interpreted. The eighteen hostile behaviors
are all covered, but hostile case 1 is intentionally represented by those
same guaranteed-positive events rather than emitted a second time. The emitted
workload is therefore exactly `40` guaranteed-positive events plus `17`
additional hostile events (codes 2–18): `57` events and `44` expected Metric-A
opportunities per episode. Across three episodes this is `171` events and
`132` expected opportunities, well above the frozen minimum of `30`.

For a challenged target, an opportunity exists exactly when, immediately
before the witness:

1. the target has the correct semantic value and is `COMMITTED`;
2. at least two effective grounded support paths justify it;
3. at least two of those paths have pairwise disjoint canonical grounded
   world-root identities;
4. the witness invalidates at least one path; and
5. at least one independent path existed before the witness and remains
   grounded immediately after it.

Success requires all of the following: the target remains continuously
committed; the invalidated path is no longer grounded; a pre-existing
independent survivor remains grounded; and no post-witness support creation,
revocation-plus-recomputation, duplicate lineage, or shared-invalidated-root
case is credited as preservation. Cases with no qualifying pre-existing
alternate are non-opportunities and are classified separately.

Independence is computed from canonical grounded root-support lineage. It is
not inferred from support IDs, immediate parent claim keys, labels, prose, or
Python object identity. A root identity hashes the complete numeric world
packet; a path identity hashes its canonical set of grounded world roots.
Shared roots, duplicate lineage, partial overlap, and a path created only
after the witness cannot fabricate an opportunity.

The evaluator serializes every challenged target with its pre-witness path
counts, independent-root count, invalidated paths, surviving pre-existing
paths, post-witness status, recomputation attempt, new post-witness paths,
primary classification, and Metric-A/Metric-B booleans. These labels are
evaluator-only and are absent from the mechanism frame.

The Metric-A gate is opportunity count at least `30` and exact rate `1.0`.
The result must also report successes and opportunities, never a rate alone.
The formal gate additionally requires `false_opportunity_classifications ==
0`. A false opportunity classification is an evaluator-labelled Metric-A
opportunity for a case whose frozen graph contract lacks a qualifying
pre-existing independent surviving lineage.

## Metric B and safety

Metric B, `recomputed_after_parent_change`, is carried forward unchanged:
global precision and recall use exact true-positive, false-positive, and
false-negative counts, with at least `30` opportunities and both precision
and recall equal to `1.0`. Alternate challenge events do not receive
`recomputation_targets`, so they cannot double-credit Metric B.

Safety gates remain:

```text
false durable claim rate  = 0
rollback recall           = 1
stale support survival    = 0
duplicate support rate    = 0
orphan support rate       = 0
support DAG integrity     = true
active store bound        = true
deterministic replay      = true
```

Production scoring uses `IncrementalProvenanceStore`. The
`ReferenceProvenanceStore` is retained as the semantic oracle and test
implementation. The dirty-cone store, canonical support identity, transitive
lineage representation, and support semantics are unchanged from 0.2.

## Controls

The same recorded mechanism stream is replayed through seven independent
implementations:

1. `DUAL_AUTHORITY`: witness, DAG, grounded provenance, and recomputation;
2. `DIRECT_COMMIT`: immediate prediction commitment;
3. `CONFIDENCE_COMMIT`: immediate commitment at the frozen `0.50` threshold;
4. `DAG_NO_WITNESS`: dependency DAG without world witnesses;
5. `WITNESS_NO_DAG`: flat witness retraction;
6. `WITNESS_PLUS_RECOMPUTE_NO_DAG`: real flat witness plus recomputation,
   without provenance query capability;
7. `DAG_PLUS_WITNESS_NO_RECOMPUTE`: DAG and witness retraction without
   recomputation.

No control winner is assumed. Report actual false-knowledge, rollback,
preservation, recomputation, coverage, stale-descendant, runtime, and state
counts side-by-side. Distinguish final-state correctness from knowledge-
maintenance capability.
